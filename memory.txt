1. WHAT THIS PROJECT IS
================================================================================

An AI-powered MCQ generator for Kazakhstan's National Testing Center (NTC,
Ұлттық тестілеу орталығы / ҰТО). Questions are written in Kazakh for
TEACHER CERTIFICATION exams (NOT student admissions — that's a DIFFERENT
exam called UNT). Two subjects:
  - Mathematics (in Kazakh + LaTeX)
  - Kazakh language / literature

Research goal: generate 300 questions total = 3 LLMs × 50 questions × 2
subjects. The 3 chosen LLMs:
  - openai/gpt-4o-2024-11-20
  - anthropic/claude-sonnet-4.6   (slug unverified against OpenRouter; the
                                  --model flag is the escape hatch if 404)
  - qwen/qwen-2.5-72b-instruct

Generated questions will be expert-evaluated and submitted to a journal.

3. PAPER NOVELTIES (the differentiators reviewers will ask about)
================================================================================

Three contributions agreed with user, all implemented:

(1) CRITIC DISCRIMINATION INDEX (CDI) — src/cdi.py + scripts/compute_cdi.py
    Metric that validates a critic agent WITHOUT expert grading. Compares
    critic scores on real NTC items vs. programmatically-degraded variants
    (wrong-answer-key relabel, weak-distractor substitution). Reports per-
    dimension mean gap, Wilcoxon signed-rank p-value, Cohen's d for paired
    samples. Renders Markdown + LaTeX + JSON. Not in the 23-paper lit review;
    publishable as named contribution.

(2) MULTI-CRITIC ENSEMBLE — src/ensemble.py
    EnsembleCriticAgent runs N critics in parallel (default: GPT-4o + Claude
    Sonnet 4.6 + Qwen-2.5-72B, three vendors) via ThreadPoolExecutor.
    Aggregates: majority-vote answer, mean per-dimension scores, agreement
    fraction. Calibration script reports pairwise Cohen's κ across critics
    as inter-rater-reliability-among-models (paper claim).

(3) SYMBOLIC SELF-VERIFICATION — src/symbolic.py + tests/test_symbolic.py
    Math generator emits a Python snippet that re-derives the answer with
    SymPy. Critic runs it in a hardened subprocess sandbox before scoring.
    Three outcomes:
      - Code stdout ≠ expected_output → correctness=0, hard reject
      - matches_option ≠ correct_answer → same hard reject
      - applicable=false or sandbox error → fall back to LLM-only
    Catches arithmetic hallucinations. Extends Kadyrov et al. 2025 (+27%
    UNT accuracy with SymPy) to the GENERATION side. 28 unit tests pass.

8. CRITICAL DESIGN DECISIONS
================================================================================

Cross-model critic:
  CriticAgent uses self._text_model / self._vision_model, set at init time
  from config OR via per-instance override (EnsembleCriticAgent uses this).
  Default: critic_model mirrors config.model (zero regression).

Vision routing:
  Critic uses config.vision_critic_model (default GPT-4o) ONLY when
  figure_path is set AND that model is in VISION_CAPABLE_MODELS allowlist
  in src/agents.py. Otherwise text path. Image is base64'd as data: URL.
  Cost saver: ~8-10 image questions per 50-batch pay vision premium; the
  rest stay cheap.

Symbolic sandbox (THIS IS RESEARCH-GRADE, NOT AIRTIGHT):
  - subprocess isolation via `python -I -c ...`
  - Denylist (not allowlist) — too many SymPy transitives for allowlist
  - Pre-import sympy/numpy BEFORE installing hook → their deps bind once
  - sys.modules['subprocess'] etc. set to None after pre-import
  - os.system / os.popen / os.remove / etc. set to None on os module
  - importlib.import_module patched to enforce the hook
  - 5-second wall-clock timeout
  - `open` is NOT blocked (mpmath needs it) → file writes possible
  - `breakpoint` IS blocked
  - 11 attack vectors tested in tests/test_symbolic.py — all blocked
  - Documented as needing Docker/firejail for production

Per-model output paths:
  output/<subject>/<model_slug>/level_<X>/<timestamp>_<id>.{json,md}
  model_slug = config.model.split("/")[-1] (e.g. "gpt-4o-2024-11-20")

Ensemble persistence:
  Question.ensemble (Optional[dict]) carries the full per-critic breakdown:
  {aggregated, per_critic, answer_agreement, unanimous, n_critics_*}.
  Single-critic runs leave it null — serializes identically to before.

Critic verification persistence:
  CriticFeedback.verification (Optional[dict]) carries the Verdict.to_dict()
  output: {applicable, ran, passed, contradicted, note, raw, [self_inconsistency]}.

Pass thresholds:
  overall_score >= 6.0 AND correctness >= 7 → question saved
  (the correctness hard rule is enforced in generate.py:177 / run_batch.py)
  Symbolic verification can OVERRIDE: contradiction → correctness=0 (always fail);
  pass → correctness floor=9 (don't let hedging LLM critic reject)

9. THE LITERATURE LANDSCAPE (must-know-papers)
================================================================================

Abdrasilov et al. 2026 (paper 21 in lit review):
  CLOSEST COMPETITOR. Same country, same testing center ecosystem.
  BUT: targets STUDENT UNT exam, not TEACHER NTC. One hybrid model
  pipeline (GPT-Oss 120B + Gemini 2.5 Pro), not 3-model comparison.
  Human-in-loop only, no critic agent.
  Differentiation: NTC vs UNT, multi-model, automated critic + CDI +
  symbolic verification.

  IMPORTANT: Bolatbek Abdrasilov also co-authored Kadyrov et al. 2025
  (paper 1). So he's an active researcher at NCT — be careful with
  positioning. If user is affiliated with him, this becomes "extension
  of our prior work" rather than "competitor."

Kadyrov et al. 2025 (paper 1):
  Evaluates 6 LLMs on 139 UNT math items in Russian. Showed SymPy
  augmentation gives +27% on Claude, +40% on Llama. Direct cite for
  our novelty #3 (symbolic verification).

He et al. 2023 (paper 6):
  Chinese ChatGLM for National Teacher Certification Exam. STRUCTURAL
  SIBLING — same target (teacher cert) but different language. Cite as
  methodological precedent.

Yao et al. 2025 (MCQG-SRefine, paper 12):
  4-step iterative self-refine with LLM-as-judge. Direct precedent for
  novelty #2 (ensemble). Their Cohen's κ between expert raters was 0.667;
  our pairwise-κ among models is the analog.

Byun & Choi 2025 (D-GEN, paper 9):
  Notes LLM-as-judge is unreliable for fine-grained dims. Motivates our
  ensemble + CDI as alternatives to single-LLM-judge.

Lu et al. 2025 (TCM-Align, paper 5):
  Dual-summary self-consistency filter. Inspired our verification design.

KazMMLU (Togmanov et al. 2025) + Maxutov et al. 2024 + Toleu 2025 +
Muhetaer 2025: low-resource Kazakh background. Cite to motivate the
language difficulty.

PersianMCQ-Instruct (Zeinalipour et al. 2025):
  Closest low-resource generation pipeline (Persian, Wikipedia-sourced).
  Different in that they FINE-TUNED on their generated dataset; we don't.

13. SCHEMA CHEATSHEET
================================================================================

GeneratedQuestion (raw LLM output):
  topic, question_text, options [4×{label,text}], correct_answer,
  explanation, latex_formulas [list], figure_spec [opt],
  verification [opt] = {applicable, code, expected_output, matches_option}

CriticFeedback:
  critic_solution, critic_answer, dimensions {6 floats 0-10},
  overall_score, pass_fail, comments, improvement_suggestions [opt],
  verification [opt] = {applicable, ran, passed, contradicted, note, raw,
                        [self_inconsistency]}

Question (saved JSON):
  Everything above + id, subject, level, format, topic, model_id,
  figure_path, critic_score, ensemble [opt dict], timestamp,
  generation_attempts

EnsembleCriticFeedback (in-memory only):
  aggregated: CriticFeedback (synthesized verdict the pipeline uses)
  per_critic: list[PerCriticResult]
  answer_agreement: float [0-1]
  unanimous: bool
  n_critics_responded / n_critics_failed

CDI output:
  {summary: {n_real_items, n_critic_failures},
   wrong_key: {dim: DimensionCDI {...}},
   weak_distractors: {dim: DimensionCDI {...}}}
  DimensionCDI: dimension, variant, n_pairs, mean_real, mean_degraded,
                sd_real, sd_degraded, gap, wilcoxon_p, cohens_d, interpretation
